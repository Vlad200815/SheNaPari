# Стан проєкту

[← До README](../README.md)

Стан на **24 листопада 2026**. Проєкт є MVP курсової роботи: увесь шлях замовлення від меню до видачі за QR працює наживо на трьох частинах системи. Оплата й SMS імітуються, а адміністратор працює через Swagger.

### Інфраструктура

- Flutter pub workspace зі спільним пакетом `shenapari_core`.
- GitHub Actions: сервер (збірка з `-warnaserror`, тести, перевірка незастосованих міграцій, перевірка вразливих пакетів) і мобільні застосунки (`build_runner`, `flutter analyze`, `flutter test` для пакета, клієнта й кухні).

- Конфігурації запуску для Android Studio в `.run/`.

## Спрощено в MVP

| Що | Як зараз | Що знадобиться для реального запуску |
|---|---|---|
| **Оплата** | імітується: кнопки Google Pay і Apple Pay лише записують спосіб оплати, гроші не списуються, «повернення» змінює статус запису | платіжний провайдер (LiqPay, WayForPay, Stripe тощо) і підтвердження оплати від нього |
| **SMS** | `LogSmsSender` пише код у консоль сервера | реалізація `ISmsSender` для SMS-провайдера (TurboSMS, Twilio тощо) |
| **Адмін-панель** | ендпоінти `/admin/*` готові, інтерфейсу немає, адміністратор працює в Swagger | вебпанель або екрани в застосунку кухні |
| **Push на iOS** | немає (потрібен Apple Developer account); на iPhone статуси оновлюються через SignalR, поки застосунок відкритий, а стрічка під дзвіночком працює | акаунт розробника Apple, APNs-ключ у Firebase |
| **Хостинг** | сервер працює на ноутбуці розробника; для демо його відкриває ngrok | сервер або хмара, HTTPS, постійна база |
| **База даних** | SQLite, один файл | для кількох екземплярів сервера — PostgreSQL або SQL Server (EF Core дозволяє змінити провайдера) |
| **Їдальня** | одна: таблиця `Canteens` існує, але сервіси беруть перший рядок | вибір їдальні в застосунку й прив'язка меню, замовлень і персоналу до неї |
| **Відновлення пароля персоналу** | лише через адміністратора (`POST /admin/employees/{id}/password`) | скидання паролю через email |

## Не реалізовано

- **Перегляд оцінок.** Сервер зберігає оцінки, але жоден ендпоінт не віддає їх кухні чи адміністратору: `StaffOrderDto` не містить `rating`. Побачити їх зараз можна лише в базі.
- **Статистика для адміністратора**: виручка, популярні страви, середня оцінка. Є лише список замовлень за день (`GET /admin/orders`).
- **Push для кухні.** Застосунок кухні дізнається про нові замовлення лише через SignalR, поки він відкритий.
- **Англійська в застосунку кухні.** Свідомо лише українська (`registerCore(onlyLanguage: 'uk')`).
- **Меню без мережі.** Без зв'язку головна показує помилку. Офлайн працюють лише кошик і юридичні документи.
- **Crashlytics та Analytics.** Пакети `firebase_crashlytics` і `firebase_analytics` є в `pubspec.yaml`, але в коді не ініціалізуються.
- **Віджет на головному екрані телефона або Live Activity** зі статусом замовлення.
- **Стрічка сповіщень** показує лише останні 50 записів, без посторінкового завантаження.

## Відомі обмеження

- **Номер замовлення** — це кількість сьогоднішніх замовлень + 1, порахована перед вставкою (`OrderService.CreateAsync`). Унікального індексу на нього немає, тому два одночасні замовлення теоретично можуть отримати однаковий номер. QR-видача від цього не страждає, бо вона працює за `PickupToken`.
- **Зміна розкладу** не переносить уже зроблені замовлення: їхні перерви лишаються в базі.
- **JWT-ключ** задано лише в `appsettings.Development.json`. Для запуску в Production його треба передати через конфігурацію (`Jwt__Key`), інакше сервер не стартує.
- **Ключ Firebase** читається з `backend/secrets/firebase-adminsdk.json`. Без нього сервер працює, але push лише пише в лог.
