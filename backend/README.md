# SheNaPari — бекенд

ASP.NET Core (.NET 10) + EF Core + SQLite + SignalR. API для клієнтського застосунку та застосунку кухні.

## Запуск

```bash
cd backend
dotnet run --project src/ShenaPari.Api
```

- Swagger відкриється сам: http://localhost:5041/swagger
- База — файл `src/ShenaPari.Api/shenapari.db`. Вона створюється й наповнюється при першому запуску:
  демо-меню, два розклади дзвінків, тестові акаунти персоналу. Щоб почати з чистої бази, видаліть цей файл.
- Сервер слухає всі мережеві інтерфейси, тож телефон у тій самій Wi-Fi мережі відкриває його за
  адресою `http://<IP комп'ютера>:5041` (Android-емулятор — `http://10.0.2.2:5041`).

## Тестові акаунти (лише режим розробки)

| Роль | Вхід | Пароль |
|---|---|---|
| Суперадмін | `superadmin@shenapari.local` | `SuperAdmin123!` |
| Кухар | `cook@shenapari.local` | `Cook12345!` |
| Клієнт | будь-який номер `+380XXXXXXXXX` | код з'являється в консолі сервера |

У Swagger: `POST /auth/staff/login` (або `/auth/otp/request` → `/auth/otp/verify`), скопіювати
`accessToken`, натиснути **Authorize** і вставити його.

## Формат відповіді

Кожна відповідь, успішна чи ні, має одну форму; HTTP-коди при цьому справжні (400, 401, 403, 404, 409, 429):

```json
{ "succeeded": false, "message": "Замовлення ще не готове", "data": null, "errors": ["order.not_ready"] }
```

Усі коди помилок зібрані в `src/ShenaPari.Api/Common/Errors.cs`.

## Життя замовлення

```
Paid → Accepted → Cooking → Ready → PickedUp
  └───────┴→ Cancelled         └→ NotPickedUp
```

Замовлення створюється вже оплаченим (оплата — імітація). Кухар приймає його й називає час
готовності (5 / 10 / 15 / 20 хв), далі «Готується» → «Готово» → видача за QR. Скасувати можна
до початку приготування. Не забране за 30 хв після «Готово» закривається автоматично.
Правила переходів: `Orders/OrderStatusRules.cs`.

## Ролі

`SuperAdmin` ⊃ `Admin` ⊃ `Cook`; окремо `Customer`.

| Шлях | Хто |
|---|---|
| `/auth/*` | усі |
| `/categories`, `/dishes`, `/breaks`, `/canteen`, `/me` | будь-хто з токеном |
| `/orders/*` | клієнт |
| `/staff/*` | кухар і вище |
| `/admin/*` | адмін і вище (адмінів створює лише суперадмін) |

## Події в реальному часі (SignalR, `/hubs/orders`)

| Подія | Кому | Коли |
|---|---|---|
| `OrderCreated` | персонал | нове замовлення |
| `OrderStatusChanged` | власник замовлення і персонал | будь-яка зміна статусу |
| `CanteenChanged` | усі | кухня призупинила або відновила прийом |

Токен передається як `?access_token=...`.

## Push-сповіщення

Працюють через Firebase Cloud Messaging. Ключ сервісного акаунта лежить у
`backend/secrets/firebase-adminsdk.json` (папка в `.gitignore`, **ніколи не комітити**).
Без ключа сервер працює, а сповіщення лише пише в лог.
